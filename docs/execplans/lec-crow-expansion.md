## Architecture and safety constraints

Authored mechanics → one canonical record/ordered IO contract → generated target assets/maps → native physics owner and bounded reference client → existing AARNN runtime. No physics adapter becomes a neural kernel or derives biological time from arrival. Simulation source time is 2 ms; wall time only paces and measures latency. Each instance has separate identities, sockets, filters, queues and reset state. Duplicate brain/endpoint assignments are rejected.

Native MuJoCo owns model/data on one thread; exact 3.17 headers generate minimal FFI. Runtime version is checked before struct access. Rust AER input/output channels have capacity two and 4 MiB frame limits. Full pre-admission input mailboxes record gaps; output backpressure does not silently discard committed neural events. Reference effects expire after 100 ms of source steps and disarm without stopping physics.

The Rust service binds loopback, requires a random private 0600 token, rejects foreign origins, bounds command credits, separates emergency stop, and has one physics owner. Viewers publish no sensory frames. Reset/restore disconnect, advance epochs and inhibit actuation; no remote brain reset occurs. Local embodiment checkpoints exclude remote brain/in-flight transport and cannot certify deterministic closed-loop replay. Saved active output is not replayed.

Webots fixed-link clusters aggregate mass/COM/inertia exactly, then reparent articulated children and collision geometry to their physics owner. This avoids massless fixed supports and NULL-Physics gaps. Original source names remain in the map. Passive rollers remain uncommanded by AER. Linear equality grippers use declared paired compliant efforts; logical coupled motors are not mechanical constraints. No hidden servo holds an unpowered body.
