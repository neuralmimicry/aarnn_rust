## Fixtures and measurement profiles

Define versioned, deterministic fixtures with recorded seeds and hashes:

- **F1, microanatomy:** 12 neuron owners; sensory/hidden/output roles; variable-radius axon and dendrite paths; hillock; a bifurcation; a crossing without junction; one unattached growth tip; a bouton, postsynaptic site and real synaptic gap; tissue boundary; known active and retired IDs. Each quantity is a declared model fixture, not an empirical biological measurement. Include a marker lacking dimensions and a path lacking a radius as negative cases.
- **F2, geometry edge cases:** coincident samples, sharp bend, reversal, near-zero segment, huge world origin, tiny radius, camera inside a soma/membrane, off-tile owner with crossing path, removed waypoint anchor, bad number, conflicting ID and stale revision. Expected validity is specified per case; do not admit malformed geometry just to keep rendering.
- **F3, time series:** two compatible geometry revisions with one atomic structural activation; an in-flight event admitted on the old route; known path travel/release/receive tags; same-tick different-microstep events; an explicit telemetry gap; controlled out-of-order/duplicated delivery. Include frozen, recorded-live and isolated-replay modes.
- **F4, interactive performance:** 4,096 visible somas, 32,768 paths, 500,000 centre-line samples and at most 5 million submitted triangles in a bounded region. All physical metadata is valid. Publish exact contact count, final tessellation count and byte sizes; do not hide dynamic LOD reduction. Include a separate million-node spatial-index source with the same local view to test locality, not whole-brain high-detail rasterisation.
- **F5, controlled actual runtime:** a reproducible locally hosted AARNN run that publishes its own committed geometry/activity with authorised recording. Use fixed inputs/seeds, stop criteria and runtime profile. Identify any currently missing physical-data/activation gate as blocked. A fabricated fixture must not substitute for this gate.
- **F6, startup and incomplete-import build:** the shipped default 3x70 model, a zero-connection model and point-only imports with missing or conflicting units/radii/routes. Retain original bytes, declared transformation policy, seed, identity map and admission outcomes. A short generated PCM stimulus is checked into QA; the local `/home/pbisaacs/Downloads/message.wav` remains a manual reproduction input and is not copied into the repository.

The baseline workstation target is Ubuntu, ≥8 CPU cores, 32 GiB RAM and 8 GiB GPU memory; record actual CPU/GPU/driver/OS/browser/backend/encoder and resource limits. Add ARM64 headless and CPU fallback lanes. Warm up for 30 seconds, measure at least 120 seconds, repeat matched baseline/treatment five times, and retain raw timing distributions and digests. Report p50/p95/p99, throughput, source age, dropped/coalesced visual samples, RAM/VRAM, queue sizes, storage and tile hit rate. Do not infer a percentile from averages. Fix identical runtime inputs and explicitly account for external real-time input scheduling when comparing digests.

## Evidence and exactness rules

Each result bundle contains requirement mapping, source commit and dirty state, command/profile, fixture and configuration hashes, seed, product/backend/driver, logs, status, timing/memory statistics, selected/effective stage, coverage/gaps and output checksums. Include images/video where visual output is the subject. A successful shader compile or image file existence is not visual acceptance.

For physical geometry compare canonical samples exactly and generated surfaces against declared tolerance. Camera tolerances distinguish floating-point backend differences from visible drift. For signals compare authoritative event identity/tag, route epoch and timing; do not use screenshots as the sole causality oracle. For export verify every frame can decode, counts/dimensions are correct and no unexpected black/duplicate/missing segments occur. Intentional fades or held frames belong in the plan. Cross-encoder container bytes may differ even when tracks are equivalent.

Required named future lanes, to add to xtask after discovery: high-detail-contract, high-detail-native, high-detail-browser, live-capture, fpv-camera, fpv-export-recovery and visualisation-performance. These are proposed names, **not runnable current commands**. The implementing agent shall document the final exact commands and CI prerequisites once registered. Existing baseline commands are listed in the source audit.

## Visual review rubric

P0 release requires all applicable items to pass: genuine 3D occlusion; continuous but unaltered branching; preserved gaps; readable somas/contacts at close range; stable materials/identity; no boundary-following pipes; no geometry jumps during tile updates; no invented signal pulses; smooth camera trajectory; visible incomplete/stale state; legible scientific overlays; and correct actual-network provenance. P1 cinematic review additionally checks highlight clipping, bloom leakage across gaps, transparent sorting, focus pumping, temporal ghosting and compression flicker. The reference artwork is not a pixel-match target.
