# Live neural visualisation and FPV animation — requirements v1.0

Date: 30 September 2026. Intended implementer: Codex in JetBrains RustRover.
Repository: https://github.com/neuralmimicry/aarnn_rust
Inspected baseline: `0c561abe210238e3dfabeb81a667f541d7d0b38f` (package 0.1.37).
Status: implementation requirements; not a claim of implemented or benchmarked capability.

## 1. Outcome and authority

An authorised user shall be able to select high anatomical detail, explore an actual running NeuralMimicry network in three dimensions, inspect individual structures and activity, plan a reproducible first-person camera journey, and download an animation generated from that network's committed geometry and recorded activity. A headless server shall continue running the brain when viewers disconnect or an export fails.

The visual ambition comes from the luminous, spatially intricate neuron imagery in the reference film and the NeuralMimicry concept film: convincing depth, continuous branches, readable contacts, smooth movement and clear activity. Those images are art direction, **not geometry, measurements, biological evidence or replacement footage**. Acceptance requires rendering actual AARNN data. No pre-rendered stock neurons, invented filaments, decorative connections or generated image sequences may stand in for the network.

This specification supplements `docs/specifications/morphology-and-responsive-simulation.md` and the existing FPV plan. Preserve `AGENTS.md`, `.agent/PLANS.md`, `distributed-whole-brain-emulator-v1.1.md`, all `INV-001..017`, and applicable product invariants. Existing `VIS-09..12`, especially clearance, radii, colour identity and presentation-only timing, remain normative. This is not permission to bypass incomplete distributed activation gates or to change the electrical model. Resolve genuine semantic conflicts through an ADR and the repository's specified approval boundary; ordinary implementation choices should proceed autonomously.

Use the accompanying source audit and ExecPlan. Revalidate symbols against the user's checkout before editing. Do not overwrite the existing AGENTS.md, FPV plan or morphology plan. Track the new work as a feature plan with links to those plans.

## 2. Existing foundation and important limits

The code already provides nine detail stages, immutable bounded display DTOs, anatomical provenance, a clearance witness, stable-ID encoding, native and web views, Android FPV planning, owner-scoped persistent render jobs, frame leases, FFmpeg MP4 output and an isolated replay path. Extend these capabilities.

The inspected browser dashboard uses Canvas 2D. Native anatomy uses projected egui mesh geometry. `render_frame_ppm` projects paths into CPU strokes and somas into discs; it has no shared 3D depth-buffered surface renderer. Current FPV waypoints identify neurons; camera targets interpolate linearly and the eye is derived from scene extent and zoom. A job normally captures a static `DisplaySnapshot` and active IDs. Isolated replay changes active IDs, but does not provide a full captured morphology/activity timeline.

Crucially, `live_morphology_display_snapshot` retains legacy live paths with missing physical soma radii and zero path radii. The existing high-stage gate correctly prevents these from masquerading as verified volumes. A renderer upgrade alone cannot fix that data gap. Migration to authoritative physical geometry is an explicit delivery dependency, not an excuse to invent radii or set the witness to true.

## 3. Scope and delivery priorities

P0 is mandatory for a truthful usable release: versioned data, safe live viewing, high-detail geometry, real activity capture, FPV camera control, reliable headless export, compatible jobs, download integrity and acceptance evidence. P1 improves production quality after P0: richer lighting, cinematic effects, 4K throughput optimisation and mobile presentation improvements. Desktop Ubuntu and the web client receive the complete interactive experience first. Existing Android and native FPV submissions must remain compatible. iOS must retain supported display/policy behaviour; a new iOS FPV planner is a separate explicitly reported milestone, not an assumed existing feature.

Out of scope: changing neural learning rules or delay physics; introducing a cable-equation solver; manufacturing missing biological anatomy in the renderer; introducing glia or myelin where the model has no such records; making export replay actuate hardware; changing neural fidelity because a GPU is busy; marketing-only videos. Point-only reconstruction continues through its existing governed producer/admission path and is labelled procedural.

## 4. Modes, truth and user control

**NVR-001 — Separate representation, rendering quality and time source (P0).** Preserve the nine stages and Auto. Independently select Scientific or Cinematic presentation and one of Live, Frozen snapshot, Recorded live capture, or Isolated replay. Show requested stage, effective stage, source mode, data age and unavailable-detail reason. High detail selects stages 8/9 when authorised data supports them. Manual selection must not silently become synthetic layout or lower anatomical semantics. On resource pressure, explain the effective fallback; offer reduced region, slower frame rate, or export. Never change the simulation to satisfy display settings.

**NVR-002 — Provenance is inspectable (P0).** Distinguish observed anatomy, committed procedural anatomy, schematic topology, missing geometry and modelled versus measured quantities. A live recording and a replay are distinct sources even when visually similar. Inspectors and exported metadata expose brain/run identity, source commit, model/config digest, geometry and topology revisions, coordinate frame/units, capture interval and completeness. Offline files must not display a live status. Stale activity cannot remain labelled current.

**NVR-003 — Preserve simple modes (P0).** Stages 1–6 retain existing semantics, ID-safe picking and stable layouts. Stage 7 uses committed centre-lines under the existing clearance/radius gate. Stage 8 adds physical volumes; stage 9 adds committed contacts. Unsupported stages remain visibly unavailable. The physical-capability gate may only be changed by a separately justified specification revision, not by this feature.

## 5. Geometry and display contract

**NVR-004 — Publish physical geometry from the owning model (P0).** Inventory every live producer and record which fields it can actually supply. Bind soma dimensions, hillock, axon/dendrite branches, attachments, boutons, postsynaptic sites and synapses to authoritative IDs and revisioned ownership. Carry only available model structures; absence is explicit. Add model metadata through the morphology plan when genuinely needed, with units, parameter provenance, migration and admission evidence. Until that dependency passes, preserve legacy lower stages and show a precise availability reason. A beautification toggle may not authorise physical measurements.

**NVR-037 — Complete initial anatomy for new local models (P0).** A newly created default or empty model shall include a versioned physical-build policy and enough validated soma, neurite and contact data to make stages 1–9 available from its first committed model generation. A model with no neural connections must report that there are no contacts to draw while still supporting the stage-9 view and inspection policy; it must never invent a synapse. Physical radii, coordinate units, clearance and any procedural assumptions belong to the authoritative model build and its topology commit, not a renderer-side fallback. The builder shall fail or report incomplete admission explicitly if it cannot verify the requested anatomy. Existing checkpoints without physical metadata remain readable with the lower-stage capability limit until migrated through an authorised, versioned rebuild. Audio or other stimulus may alter activity presentation but does not change which anatomical stages the model can support.

**NVR-038 — Growable physical transformation of incomplete imports (P0).** An import missing units, radii, routes or contact dimensions shall be treated as source data requiring an explicit versioned transformation before it can claim all visual stages. Keep the original positions/connectivity and provenance; record coordinate mapping, modelled dimensions, deterministic reconstruction seed, admitted/rejected routes, clearance evidence and a stable identity map. Publish the transformed anatomy through the same ownership and logical-boundary rules as new models so subsequent growth updates the executable topology and the displayed physical geometry together. A rejected connection remains visible as schematic graph topology with its reason; neither an import nor later growth may draw that route as a committed neurite or synapse until admission succeeds. Import, restart and later growth must retain deterministic transformation and checkpoint compatibility evidence.

**NVR-039 — Automatic physical calibration provenance (P0).** New default models and imports with incomplete physical data shall apply a deterministic, versioned heuristic size/scale policy automatically, using declared measurements where valid and a labelled modelled prior otherwise. The record shall retain source units or their absence, original positions, estimator inputs, estimated conversion, radii, clearance and gap, and every admission or repair outcome. A heuristic estimate is not an empirical measurement or a clearance witness. Repeated builds and checkpoint restore must reproduce the record and geometry; an estimate that cannot be safely admitted reports a specific failure while preserving source data and schematic connectivity.

**NVR-005 — Preserve samples and branch structure (P0).** Evolve `DisplayPath` compatibly to represent radius at each committed sample, ordered centre-line samples, parent/attachment identity, path-local sample identity or stable order, lifecycle and geometry revision. Reuse `PhysicalPath`/`PathSample` semantics rather than inventing a second physical representation. One scalar radius in old data means a constant-radius path, not proof of taper. Preserve bends, terminal locations and owner identity; never join merely crossing projected paths. A terminal without a synapse stays an unconnected terminal. Retired structures follow their committed lifecycle.

**NVR-006 — Stable identity and colour (P0).** Use full brain/run/owner/generation identity plus stable anatomical IDs; keep 64-bit values as decimal strings across browser boundaries. Audit the legacy path-counter and layer/index mappings: they are not sufficient evidence of persistent identity across selection or topology changes. Migrate at the producer or retain an explicitly transient legacy mapping. A path may not acquire another path's animation or selection after a tile refresh. Preserve the normative adjacency-aware colour policy and fixture. If colour slots currently depend on a sampled subset, fix publication/assignment stability at the canonical producer; do not recompute colours independently in renderers. Cinematic lighting may modulate colour, not silently replace the identity palette.

**NVR-007 — Coherent scene revisions (P0).** A displayed anatomical scene must be assembled from one authorised capture root or an explicitly defined compatible revision set: brain/run, topology epoch, morphology revision, route epoch, coordinate-frame version and source sequence/cut. Reject mixed revisions, conflicting duplicate IDs, mismatched units and stale replacements. Obtain immutable tile references from the server; do not merge independently fetched live tiles and inherit the overview's revision as proof of consistency. Advance the visible scene atomically when the required local set is ready; keep the last valid bounded view, with age/coverage indicators, while rebuilding. Partial spatial coverage may render, but it may not be labelled complete.

**NVR-008 — Honest coverage and locality (P0).** Tile selection must include intersecting neurite segments and contacts even when their owner soma is outside the tile. Include bounded owner stubs or resolvable references; do not drop a nearby axon solely because its soma was not sampled. Define boundary ownership/deduplication, segment continuation, clipping and missing-neighbour indicators. Keep `coverage.region` distinct from `coverage.membrane`. Bounds and rendered scale must not change when a different subset is loaded. The aggregate completeness flag includes all omitted nodes, paths, samples, contacts and route coverage, not only the individual tiles' flags.

**NVR-009 — Geometry quality without geometry invention (P0).** Build depth-buffered 3D soma surfaces and swept neurite meshes with normals and stable, twist-minimising frames. Use committed radii, joins and attachments. Tessellation may subdivide stored segments; it may not shorten the authoritative arc length, smooth away bends, move endpoints or close a synaptic gap. If a smooth visual surface departs from the piecewise-linear physical path, define a bounded surface error, preserve the canonical path for timing/picking, prove membrane/clearance containment, and label any exaggeration. Handle duplicate samples, near-zero tangents, reversals, sharp bends and variable radii without NaNs or self-bridging triangles. Mesh LOD never writes back to morphology.

**NVR-010 — Contacts and membrane (P0).** Render the actual published tissue boundary as an optional soft enclosing surface; do not infer it from a bounding box or soma hull. Clip surfaces and footprints correctly, including when the camera is inside the membrane. Render measured/modelled bouton, postsynaptic and synaptic shapes where dimensions/orientation exist. Existing point-only markers are pickable annotated glyphs; they must not be presented as physically sized boutons. Cross-sections and exploded views are explicit inspection modes and must not alter stored coordinates. A synaptic cleft remains a gap; glow must not imply a fused tube.

## 6. Interactive renderer and visual quality

**NVR-011 — Modular renderer boundary (P0).** Introduce a canonical renderer-independent scene/camera/material/activity contract with a shared geometry builder and versioned policy. Keep simulation, capture, mesh preparation, rendering and encoding as separable services/modules. Extend existing entry points rather than making a second application or unrelated viewer. Assess reuse of the native eframe/wgpu integration and a browser-capable backend through an ADR; do not assume the robotics `webgl-world.js` is already a neural renderer. Dependency choices require the repository's normal review, licence and target checks. A shared Rust scene evaluator may be reused through WASM/FFI where feasible; do not require identical GPU binaries on all clients.

**NVR-012 — Real spatial interaction (P0).** Provide orbit, pan, dolly, six-degree-of-freedom fly-through, focus selection, reset-to-fit and bookmark views with stable world coordinates. Perspective and orthographic views must share picking and units. Use correct near/far clipping, aspect ratio, device-pixel ratio, depth testing and transparent-object handling. Pointer focus prevents FPV controls from capturing typing in other UI fields. Keyboard/touch alternatives and reduced-motion settings are required; escape releases pointer lock.

**NVR-013 — Scientific and Cinematic presets (P0/P1).** Scientific mode uses readable identity colours, calibrated legends, optional scale bars and restrained activity emission, with effects off by default if they obscure evidence. Cinematic mode may enable physically plausible lighting, tone mapping, ambient occlusion, bounded bloom and optional depth of field. It must render the same scene and timestamps. Bloom, transparency, focus blur and highlight exaggeration are visual effects, never evidence of voltage, size or connectivity. Pin settings in the render manifest. P0 includes depth, correct surfaces, anti-aliasing and deterministic materials; P1 includes expensive effects and temporal anti-aliasing with history-reset tests.

**NVR-014 — Inspect and isolate (P0).** Pick soma, individual branch/path, terminal/contact or synapse by stable ID. Show kind, owner, available physical dimensions, route length/delay, provenance, lifecycle and exact logical time when available. Missing values read unavailable. Allow hide/isolate, clipping planes, selected-route highlighting and context ghosting. These are local presentation filters. The inspector must not infer causal parentage from geometry, colour or correlated firing. Hidden geometry and clipping must be recorded if applied to exported evidence.

**NVR-015 — Graceful device capability (P0).** Detect supported render capabilities and memory budgets. Keep a functioning simpler view when GPU creation fails, context/device loss occurs or a client lacks high-detail support. Show the effective renderer and limitation. Headless rendering requires no desktop login or physical display. x86_64 and ARM64 Linux workers advertise actual GPU/CPU capabilities; no CUDA-only dependency for baseline viewing/export. CPU or software rendering may be slower and lower quality, but must be explicitly identified and geometrically truthful.

## 7. Time, live activity and morphology evolution

**NVR-016 — Read-only telemetry with logical provenance (P0).** Add a bounded activity stream keyed by stable neuron/path/synapse and event IDs, compatible scene revisions and the existing `LogicalTag` including microstep. Preserve committed status, route version and source segment/timing information where supplied. Network arrival time and the wall-clock animation timer never define neural causality. A model that exposes only active neuron IDs supports soma/owner highlighting, not a claimed travelling action potential. Voltage/energy overlays require actual fields with units and named mappings; otherwise disable them.

**NVR-017 — Display signal travel from its model (P0).** When route telemetry supports it, animate bounded emission along the committed piecewise route using source traversal times and route-specific conduction/synaptic delays. For a uniform-speed segment, displayed progress is the clamped logical elapsed time divided by its modelled duration; for variable segments evaluate the recorded timing schedule, not a global visual speed. Branch arrivals, synaptic release, receiving activity and simultaneous microsteps remain distinct. An event admitted on route epoch R continues to use its recorded route R even after growth publishes R+1, unless the authoritative model specifies otherwise. Never infer a synaptic event from mere spatial proximity.

**NVR-018 — Separate time scales (P0).** Expose live wall-clock versus biological-time lag, playback speed, paused local view, single-step recorded logical time, slow-motion activity and growth timelapse. Pausing a viewer pauses only that viewer. Sampling a millisecond event at 30 fps may miss it: permit an explicitly labelled interval-activity or exposure overlay with a recorded window, never silently extend an event's biological duration. Multiple same-frame events remain accessible in a timeline/inspector even when pixels cannot resolve them. Discrete topology commits appear at their effective logical boundary. Optional growth tweening is a labelled display interpolation and cannot show a not-yet-active synapse as active.

**NVR-019 — Capture modes and completeness (P0).** Support: (a) Frozen snapshot fly-through: static committed geometry, no assertion of ongoing activity; (b) Recorded live capture: actual geometry revisions and observed committed telemetry over a bounded interval; (c) Isolated replay: separately authorised saved state plus recorded inputs, versioned runtime and deterministic replay evidence. Do not use the current fixed-step replay helper as proof of parity with the superdense distributed executor. Build on the authoritative supported runtime mode and report its limits. Recording does not rerun or step the live brain. A downloaded movie generated later from a live capture is labelled recorded, with its original capture times.

**NVR-020 — Loss and disconnection are visible (P0).** Interactive derived telemetry may coalesce or drop visual updates according to policy; count and expose loss, age and sequence gaps. Never drop authoritative causal events. A recording requesting complete route/activity evidence must either persist a complete authorised stream within its admitted resources or terminate/mark the affected interval incomplete. Saturation may stop capture, not the brain. Default evidence exports refuse a claimed complete result from incomplete intervals; an explicitly requested best-effort movie carries visible gap markers and a completeness manifest. No invented trajectories may bridge gaps. Reconnect requests a valid base/capture cursor and handles retention expiry explicitly.

**NVR-021 — Distributed capture without a new global barrier (P0).** Reuse committed-state/checkpoint/log boundaries and existing owner fencing to identify a consistent causal cut or a documented partially covered cut. Capture manifests retain relevant shard frontiers, topology transactions, ownership terms and logical interval boundaries. Do not declare completion from silence or force unrelated shards/brains to wait for recording. If the installed runtime cannot supply a globally coherent capture, expose regional/partial capture honestly rather than claiming whole-brain synchrony.

## 8. FPV planner and camera evaluation

**NVR-022 — Explicit 3D camera tracks (P0).** Extend neuron-anchored waypoints with world-space position, target/anchor, orientation quaternion, up/roll policy, FOV or orthographic size, clip planes, timeline position, duration/easing, focus distance and visual-stage policy. Camera position and look-at target are independent. Preserve old waypoint jobs through a versioned legacy evaluator; do not reinterpret their bytes. Handle coincident waypoints, closed paths, vertical travel, 180-degree turns, disappearing anchors and scene bounds without division-by-zero or sudden flips. Define freeze/fallback/abort behaviour for a removed anchor and record the resolved choice.

**NVR-023 — Smooth, inspectable routes (P0).** Provide editable 3D paths plus the existing sampled overview, draggable handles, undo/redo, reorder, segment duration, scrub, play and save/load presets. Use a versioned continuous camera path, arc-length parameterisation for constant speed and quaternion orientation interpolation with explicit roll control. Bound acceleration/jerk for the chosen smoothing policy and avoid overshoot through tissue. Offer free-fly, orbit selected neuron, follow a recorded signal route, and guided soma-to-synapse tours. A camera travelling down a pathway is not itself a neural event. Following activity requires a recorded focus policy and deterministic tie-breaks.

**NVR-024 — Collision and near-field safety (P0).** Offer collision-aware navigation against revisioned soma/neurite volumes with a camera clearance radius; camera collision never changes biological geometry. Include an explicit scientific inside-structure/clipping mode for deliberate entry. Validate the swept camera route and not just waypoints. Preflight near/far planes, available local geometry, missing tiles, sharp turns, zero-length paths and membrane crossings. For user intent beyond loaded geometry, prefetch or report incomplete validation; absence of a tile is not empty space. A camera route may cross the tissue boundary deliberately, with a clear control.

**NVR-025 — Preview/export equivalence (P0).** Evaluate camera, stage, materials, clipping, activity and capture-time mapping from the same immutable render plan for preview and export. Show differences caused only by explicitly chosen resolution/sampling/quality settings. Resolve automatic per-frame detail deterministically from captured policy and declared budgets; do not let worker load or hardware silently change the output stage track. Separate presentation time from biological time. Persist easing, random seeds, focus track and effect settings. Preserve the current policy-v1 behaviour for old jobs; any new offline-quality policy receives a new version and golden fixtures.

**NVR-026 — Route-wide coverage (P0).** Replace up-to-16 waypoint-centred tile merging as the only capture mechanism. Sample the swept camera frusta and path corridor, including intermediate segments and near-field side views; plan version-pinned tiles and prefetch based on motion/LOD. Preview uncovered sections before submitting. A spatial index keyed to morphology revision must support neurite/volume intersection queries without scanning every neuron for each tile. Reuse the authoritative spatial service if suitable; a display cache/index is derived and disposable, never a new geometry authority. Cancellation releases tile requests and bounded GPU/CPU caches.

## 9. Live responsiveness, resource isolation and scale

**NVR-027 — Neural execution has priority (P0).** No renderer, geometry builder, spatial index rebuild, exporter or encoder may hold execution-critical locks, await network/storage while holding runtime locks, run large blocking work on runtime/control threads or wait for the UI. Publish immutable bounded references/deltas from a measured short producer path. Run expensive work in bounded background services with separate queues and cancellation. Enforce CPU, GPU, memory, network and I/O budgets so shared hardware contention also stays within the acceptance budget; process separation alone is insufficient. Do not slow biological time to make a movie real-time.

**NVR-028 — Bounded streaming and LOD (P0).** Admit explicit maximum CPU RAM, VRAM, tile bytes, in-flight requests, geometry samples/triangles, telemetry throughput, capture storage, render scratch and job concurrency. LOD uses projected error, distance and importance with hysteresis; selection pins a bounded local high-detail region. Use instancing, batching, frustum/occlusion culling and incremental mesh updates as demonstrated by profiling. A whole-brain overview is not a promise to display every neurite at maximum tessellation. Large networks are streamed regionally. Reaching a cap is a reported condition with coverage counts, not a hidden omission or allocation panic.

**NVR-029 — Stage and update stability (P0).** Retain shared stage names, geometry capability checks, measured presentation p95 and Auto dwell. Measure streaming/mesh/GPU latency separately from neural latency. Preserve camera/world origin when tiles or revisions change; use camera-relative coordinates where needed while keeping authoritative mm coordinates intact. On a stale background result, discard that derived result rather than rolling the display back. Reset temporal render history on topology/camera discontinuities to prevent ghost structures. Retain bounded cache lifetimes and demonstrate no growth over a long viewer session.

## 10. Durable headless jobs and real downloads

**NVR-030 — Extend the current job service (P0).** Keep `/api/fpv/jobs` and existing owner-scoped list/status/cancel/retry/download behaviour. New requests reference server-resolved authorised capture and immutable plan IDs. Client-supplied scene JSON cannot be accepted as verified live provenance merely because it contains a brain name or clearance Boolean; legacy uploaded scenes remain unverified imported projections. Validate counts/units/revisions before allocating. Separate record/read/render/replay authorisation where applicable, preserving current access checks. Resolve all assets locally or through authorised references, not arbitrary worker URLs.

**NVR-031 — Honest capabilities and preflight (P0).** Workers advertise render backend, supported schema/policy/shader versions, codec profiles and resource limits. Preflight returns selected backend, duration, frame count, expected coverage, conservative peak RAM/VRAM/scratch estimates, storage quota and known fidelity limits. Offer 720p/1080p at 24/30 fps as baseline; support 1080p60 and 4K24/30 only on an admitted profile. These are required supported profiles after validation, not claims of real-time rendering. CPU fallback cannot silently masquerade as the high-quality GPU renderer.

**NVR-032 — Bounded, resumable export (P0).** Preserve durable jobs, leases, cancellation and idempotent publication; add version/hash validation of intermediate frames or segments and fenced claims so a late worker cannot overwrite a newer attempt. Render a bounded frame/segment window and encode incrementally. Current uncompressed PPM scratch grows as width × height × 3 × frames: under the 8 GiB ceiling, 1080p30 lasts only about 46 seconds, despite the 9,000-frame cap. Do not simply remove the cap. Implement quota-governed segments/checkpoints and cleanup to support long movies with bounded scratch. Persist enough to resume after render-worker/gateway/encoder restart and detect damaged output. Peak-memory accounting includes RGB/readback staging, encoder buffers and temporal-effect history.

**NVR-033 — Publication is transactional (P0).** Distinguish queued, preparing capture, rendering, encoding, verifying, complete, failed and cancelled states, or equivalent versioned substatus. Frame completion is not movie completion. Progress is monotonic within an attempt; retry lineage is explicit. Publish the final artifact atomically only after container decode, frame count, dimensions, duration, stream metadata and checksum verification. Preserve completed work on retry only if capture/plan/backend hashes are compatible. Bound retention and clean orphan intermediates without deleting live leases or needed captures. Cancellation leaves a diagnosable state and stops further expensive work promptly.

**NVR-034 — Download and interchange (P0/P1).** Baseline download is a portable MP4 with H.264 and a declared pixel format, browser playback and attachment disposition. Provide a poster, provenance/plan manifest and optional caption/annotation track as a bundled ZIP; evidence users can also download a bounded capture package for reproducible rendering. Support authenticated HTTP byte ranges and resumable transfer, correct MIME/content length, safe filenames, checksum and expiry/retention visibility. A Download action must actually save the artifact; preview is a separate action. Optional P1 outputs include WebM and PNG frame sequences. GIF is an optional short low-resolution preview, not the archival/scientific master. Do not claim byte-identical MP4 files across different encoder builds.

**NVR-035 — Replay has no live effects (P0).** Isolate replay from the live engine, external sensor admission and hardware outputs. AER/audio/video inputs use the established capture-time/clock-mapping provenance and explicit permission; source tracks are optional, not silently captured. Never duplicate external effects during replay. Validate input hashes, runtime/model compatibility, route/topology history and bounded resource requirements. State/event replay equality and visual similarity are different oracles. Legacy fixed-step replay is labelled as such until its intended parity gate passes.

**NVR-036 — Cross-client compatibility (P0).** Web and Rust desktop must create, preview, submit and reconnect to the same owner-scoped jobs with common plan semantics. Android must round-trip new supported fields or report unsupported editing capabilities without corrupting plans; preserve existing job access. Generated bindings/contracts are authoritative. iOS display capability and any planner absence are explicit. Server-side download ownership checks survive links, ranges, retries and retention. A copied job ID conveys no permission. Export metadata omits tokens, internal credentials and unrequested personal sensor content.

## 11. Proposed contract boundaries

These names describe responsibilities; they are **proposed**, not claims that the structs or endpoints already exist. The implementation must reuse equivalent existing contracts and avoid duplicate identity/time types.

| Contract | Minimum contents / rules |
|---|---|
| Scene manifest | Version; brain/run/source identity; committed cut/frontiers; geometry/topology/route/frame revisions; units; source/provenance; capability reasons; owner-scoped tile references/hashes; coverage and clearance evidence reference. |
| Geometry tile | Immutable ID/hash; base revision; spatial bounds; LOD/error; stable nodes, paths with per-sample radii/attachments, contact records and owner stubs; available/missing metadata. |
| Geometry delta | Base and result revision/hash; effective logical tag; ordered additions/updates/tombstones; bounded change set; explicit transaction grouping. Missing base requires resynchronisation. |
| Activity batch | Brain/run; sequence; stable IDs and event IDs; logical interval/microsteps; revision/route epoch; supported measurements; observation type; gap/coalescing/completeness information. |
| Capture manifest | Snapshot/checkpoint references; committed interval/cut; geometry deltas and telemetry chunks; source mode; input/clock provenance where relevant; hashes; completeness; permissions/retention. |
| Camera/render plan | Version; capture ID/hash; rational frame rate and exact duration; explicit 3D camera track; mapping from frame presentation time to source logical time; stage/effect/LOD policies; clip/selection filters; seeds and resolved focus/stage tracks. |
| Job manifest | Owner and approved brain/capture scope; immutable plan; backend and encoder/shader versions; resource admission; attempt/lease state; chunk/frame checksums; artifact status and retention. |

Example semantic mapping: output frame `i` has presentation time `i × fps_den/fps_num`. A recorded time map determines the biological interval represented by that frame. It does not advance the source brain. At a topology boundary, apply the committed revision transaction before evaluating compatible activity for the relevant tag. Preserve the established equal-time/microstep order rather than reconstructing it from floating-point frame times.

API evolution should add capture, plan/preflight and artifact capabilities to the existing authenticated management/job service. Discover canonical generated contract sources first. Specify cursor/resume/base-revision errors, `unsupported_capability`, expired capture, incompatible policy, incomplete coverage and quota failures. Limits are configurable but bounded and included in response capability metadata. New schema versions are explicit; old snapshots and durable jobs remain readable by the compatibility path.

## 12. Acceptance and measurable targets

The accompanying `docs/qa/live-neural-visualisation-acceptance.md` defines fixtures, scenario IDs and evidence. These targets are proposed engineering gates, not current measured performance:

- On a declared Ubuntu workstation profile (8+ CPU cores, 32 GiB RAM and an 8 GiB GPU), a versioned local high-detail fixture should sustain p95 frame time ≤33.3 ms at 1920×1080, after warm-up. Test effective stage 9 with effects separately enabled/disabled. No performance claim is valid without recording visible nodes, paths, samples, triangles, draw calls and exact hardware/driver.
- Under the specified concurrent viewer/capture/export load, committed event/state digests remain identical; neural p99 processing latency and throughput must remain within the agreed baseline envelope, initially ≤5% regression over matched runs, with no new real-time deadline misses. If the normal workload already saturates the host, throttle/defer observer work or use separate render resources; do not relax correctness or hide the regression.
- With an admitted, fully cached desktop scene, camera input-to-visible-update p95 ≤100 ms. Network delivery latency is measured separately. Live source age is always shown; a stale threshold is a versioned profile setting, not a fake real-time guarantee.
- Export at least a 120-second 1080p30 captured-live film with bounded scratch ≤8 GiB under the default profile, then prove a 10-minute run does not grow working buffers with total duration. Final retained capture/output storage remains separately quota-bounded.
- A 60-minute view/stream/update run stays within configured caches and queue caps; no monotonically accumulating orphan GPU resources. Context loss, tab backgrounding, job cancellation and reconnect have bounded, observable recovery.
- Cross-backend geometry, camera and event timing agree exactly or within declared numerical tolerances. Pixel equality is required only for the pinned deterministic reference backend; perceptual/geometry tolerances apply across GPUs. The CPU fallback is not passed off as GPU visual validation.

At minimum retain scientific and cinematic turntables, a near-field soma-to-synapse flight, recorded spike traversal, a real morphology commit, an incomplete-data example, live-plus-export performance traces and a successfully downloaded MP4/ZIP with checksums. A fixture-only demo is insufficient: include one controlled run of the actual AARNN runtime producing its own geometry/activity. Do not use or mutate a user's production brain for acceptance without explicit authority.

## 13. Completion and migration rules

Completion means the complete vertical slice works: run a controlled brain, select supported high detail, navigate, inspect, record, plan, preview, disconnect, render headlessly, reconnect, download and verify. Implemented code without retained evidence is not a completed gate.
