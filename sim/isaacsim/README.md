# Isaac Sim physics owner

`scripts/run_sim.sh --sim isaacsim` runs an AARNN-controlled embodiment on
NVIDIA Isaac Sim 6.2 (Kit 110.4, PhysX, headless) with the same managed brain,
AER contract and trace schema as the native MuJoCo owner
(`adapters/mujoco`). Only the physics owner differs.

## What is shared and what is ported

| Concern | Isaac path | Same code as MuJoCo? |
|---|---|---|
| Brain, bridge, bindings, arm gate | `run_sim.sh` managed cluster (`start_distributed_tcp_servers`, `mujoco_bindings.py`, `tcp_aer_ipc_bridge`) | identical |
| AER1 client, handshake, `output_code` | `libaarnn_embodiment_ffi.so` via `embodiment_ffi.py` (ctypes) | identical Rust (`aarnn-embodiment::aer`) |
| Motor arbitration, graded/pulse-density and antagonist decoders, C. elegans muscles, NPC | same ABI (`nm_reference_apply` / `nm_reference_submit` / `nm_reference_motor_mask`) | identical Rust (`actuation.rs`, `celegans.rs`, `npc.rs`) |
| Zebrafish water, fly wing panels | `nm_reference_hydro`, `nm_panel_forces` | identical Rust (`force.rs`) |
| Sensor projections | `senses.py`: line-for-line port of `legacy.rs`, the C. elegans and native kinds of `world.rs`, `vision.rs` | port, verified (below) |
| Servo law, speed saturation, RFT substrate/tap | `run_isaacsim.py` | port, verified (below) |
| Dynamics, contacts | PhysX articulation from the generated USD | different engine |

`nm_reference_apply` / `nm_reference_submit` (added to the FFI, header and C#
regenerated by `scripts/generate_embodiment_ffi.py`) split `nm_reference_step`
at the physics boundary so lock-step applies each reply in the same 2 ms frame
as `aarnn-mujoco --lockstep` (the combined call adds one frame of latency).
`nm_reference_hydro` exposes the zebrafish `resistive-ellipsoid-v1` water.

Sensor-time semantics follow the Rust owner exactly: joint angles/velocities
of the new state, body frames, COM velocities and contacts of the step that
produced it, accelerations over that step. Ray proxies (ultrasonic, retina,
worm range) use `mj_ray` from the `mujoco` package bundled by `isaacsim-core`
on MJCF kinematics posed from the PhysX state, so they see the same geoms,
groups, alpha and plane extents; contacts come from PhysX contact reports.

### Validation of the port (no Isaac involved)

`--physics-owner mujoco-twin` runs the identical Python body/ABI path on MuJoCo
dynamics through the same launcher. Against the native Rust owner (30 s
hexapod reflex walk; 10 s C. elegans frozen connectome; zebrafish and UGOT
quadruped NPC/silent):

* hexapod: `qpos`, body positions and all 34 submitted sensor channels
  bit-identical for all 15 000 steps; identical 123 482 output spikes;
* worm: identical 13 958 spikes; trajectories agree to 1e-12 (float order in
  the resistive-force arithmetic) after 150 steps;
* zebrafish (hydrodynamics) and UGOT quadruped (motors, NPC): final `qpos`
  bit-identical.

In Isaac the accelerometer is a finite difference of PhysX COM velocity (the
twin uses MuJoCo's analytic `mj_rnePostConstraint` value); neither circuit
below reads it.

`tests/test_senses_parity.py` (MuJoCo venv) checks the vision-cell and servo
vectors from the Rust unit tests, the split ABI clock, and replays a native
trace (joint angles exact; ranges 99.97 %; contacts 93 % because the Rust owner
reads contacts one step behind the recorded `qpos`).

## USD conversion gaps (generator changes needed)

The runner fixes these in the stage's session layer only (never saved):

1. **Joint limits ignore MJCF `ref`** — fixed in the generator (2026-11-22):
   `scripts/embodiment_usd.py` now emits `range - ref` and records the
   reference as `aarnnJointRef` custom data on each joint. The runner's
   session-layer patch sets the same values, so it is now a no-op for limits.
2. No joint armature / passive damping (MJCF 1e-4 kg m², 0.02 N m s) — needed.
3. No physics material: MJCF friction 0.8 (worm 0.02 with `priority`) vs
   PhysX default 0.5. Emit `UsdPhysics.MaterialAPI` per geom (and a combine mode).
4. No self-collision filter for `contype=2/conaffinity=1` robot geoms.
5. Not emitted at all (runner rejects these profiles in Isaac): MJCF equality
   constraints/tendons (cofe, xbot, ugot_engineer, galbot), more than one free
   body (keenon), prismatic drives.
6. **Every checked-in `.usda` is stale** after the 2026-11-22 embodiment
   regeneration (record digests changed, USD not re-emitted). The runner refuses
   a USD whose `aarnnModelDigest` differs; `emit_stale_usd.py` re-emits with the
   unchanged generator into `target/isaacsim-usd` (not the checked-in tree):
   `target/robot-usd-venv/bin/python sim/isaacsim/emit_stale_usd.py`, then pass
   `--usd-dir target/isaacsim-usd`. Regenerate the checked-in USD with
   `scripts/embodiment_usd.py` in the pinned USD venv.

Self-collision follows MJCF `contype/conaffinity` (hexapod/worm: none; UGOT
archetypes: on, with PhysX filtered pairs). Exercised in Isaac: hexapod and
C. elegans (closed loop), zebrafish and UGOT quadruped (NPC). Mapped but not
yet run in Isaac: nao, drosophila (wing panels), the other UGOT/botinkit
archetypes. Not mapped: crow (own projection/energy model) and the rejected
cases above. One body per Isaac process.

## Install (this machine, 2026-11-22)

Isaac Sim **6.2.0.0** (newest pip release): it is tested on the 595 Linux
driver branch (this host runs 595.99, CUDA 13.2), needs Python 3.12 (system
`python3.12` 3.12.7) and glibc ≥ 2.35 (Ubuntu 26.04, glibc 2.43; 26.04 itself is
not on NVIDIA's list). NVIDIA's spec minimum is an RTX 4080/16 GB; the RTX 2080
(8 GB, Turing sm_75, RT cores) boots Kit headless and runs CPU PhysX fine.

```bash
python3.12 -m venv target/isaacsim-venv            # gitignored, ~25 GB installed
target/isaacsim-venv/bin/pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu130
target/isaacsim-venv/bin/pip install "isaacsim[all,extscache]==6.2.0.0" --extra-index-url https://pypi.nvidia.com
# Rust ABI for the runner (separate target dir; does not touch target/debug):
CARGO_TARGET_DIR=target/isaacsim-ffi cargo build --release --locked -p aarnn-embodiment-ffi
```

`isaacsim-extscache-kit` is a single 5.5 GB wheel; pip's single connection ran
at ~1 MB/s here, so the wheels were fetched with `aria2c -x16`, checked against
the index SHA-256 and installed from disk (`--no-deps`), then deleted.
Running requires accepting the **NVIDIA Omniverse EULA**: `export
OMNI_KIT_ACCEPT_EULA=YES` (the launcher refuses to start Kit otherwise).

Smoke test (Kit/PhysX boot, a cube settles on a slab at 2 ms):

```bash
OMNI_KIT_ACCEPT_EULA=YES target/isaacsim-venv/bin/python sim/isaacsim/smoke_test.py --output smoke.json
```

## Run

```bash
export OMNI_KIT_ACCEPT_EULA=YES NM_ISAACSIM_PYTHON=$PWD/target/isaacsim-venv/bin/python
NM_AUTO_AARNN_DEPTH=0 NM_AER_REFERENCE_DATA_TIMEOUT_MS=60000 NM_CLUSTER_NODES=1 RAYON_NUM_THREADS=2 NM_DISABLE_OPENCL=1 \
scripts/run_sim.sh --sim isaacsim --robots hexapod=1 --no-build --headless --steps 15000 --lockstep \
  --network-map hexapod_0=network_hexapod_reflex.json --config-map hexapod_0=webots_world/configs/config_hexapod_reflex.json \
  --output run.json --trace trace --trace-every 10 --usd-dir target/isaacsim-usd
python3 scripts/qa/probe_embodiment_motion.py trace/hexapod_0.jsonl
target/robot-mujoco-venv/bin/python sim/isaacsim/compare_traces.py MUJOCO.jsonl trace/hexapod_0.jsonl --run-json MJ.json run.json
```

Options mirror `aarnn-mujoco` (`--lockstep`, `--realtime`, `--control`,
`--trace/--trace-every`, `--reference-binding(s)`, `--arm-file`); extra:
`--usd-dir`, `--device cpu|cuda`, `--physx-threads` (default 0: step on the
calling thread, fastest for one small articulation), `--physics-owner
mujoco-twin` (diagnostic). Evidence JSON adds `stage_overrides` and
`conversion_check.max_link_vs_mjcf_kinematics_error_m` (PhysX link poses vs
MJCF forward kinematics of the same joint state).

### Why the gaits differ

* **Contact model.** MuJoCo contacts are soft (solref 0.02 s): feet sink
  ~5 mm deeper (lowest root 0.052 vs 0.058 m) and lightly loaded feet make and
  break contact between consecutive 2 ms steps (2–3x more transitions). The
  circuit's load feedback (contact excites stance, suppresses swing) releases
  swing sooner in MuJoCo: higher stepping rate, lower duty factor, more lateral
  wobble (longer path). PhysX's rigid TGS contacts hold the foot down, so Isaac
  steps ~10 % slower with the same net travel (−2.5 %). The worm (friction
  0.02 under resistive-force drag) shows the same pattern: equal net crawl
  (−4 %), less contact jitter, shorter path.
* **Drive gains are not a source**: kp/kv/force range/speed saturation are the
  MJCF values on implicit PhysX drives; passive joint damping is folded into
  the drive (so it shares the force clamp — negligible here).
* **USD conversion** needed the session-layer corrections listed above; without
  the `ref` limit shift the hexapod's femur/tibia would start outside their
  PhysX limits (the passive-collapse match above depends on it).
* **Latency** is the brain's (identical code); Isaac's Python body adds
  ~2.5 ms of wall time per step, which only matters outside lock-step.
