# Isaac Sim boundary

The local USD files in `sim/content/embodiments/generated/` are native physics
articulations with named joints, mass/inertia and initially disarmed drives.
Galbot references its immutable official USD and retains its original variants.
The other models are generated by `scripts/embodiment_usd.py` using **USD 26.5**
in a separate offline conversion environment. USD parsing does not execute Kit,
PhysX, sensors or AER.

No supported Isaac installation was found locally or on the four user-designated
SSH test hosts on 2026-10-23. Native startup, articulation reset, joint efforts,
sensor acquisition, crow aerodynamic application and asynchronous AER integration
remain acceptance work. The launcher fails clearly when the required separate
`NM_ISAACSIM_PYTHON` is absent. Never run Isaac under the MuJoCo venv.

API research: `https://docs.isaacsim.omniverse.nvidia.com/latest/py/source/extensions/isaacsim.core.experimental.prims/docs/index.html`
uses `Articulation(paths)`, `dof_names`, `get_dof_positions`,
`set_dof_efforts` (called each physics update) and zero drive gains for effort
control. Pin the installed Isaac release and revalidate this API before enabling
a runner. The USD converter does not import `omni.isaac` or bootstrap Kit.

The RTX 2000 Ada host reports 16 GB total VRAM but was already using most of it;
no workloads were stopped to obtain memory. Installing/running a suitable Kit
runtime and validating its hardware policy is still required. No ROS dependency
is introduced for AER.
